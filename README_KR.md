## 1막: 20년 전 그 사람

나는 게임을 좋아했다. 내가 25살 무렵 경찰공무원 준비한다고, 고시원 생활할때, 한국에서는 리니지2가 제법 인기 있었고, 프리서버가 활발했던 적이있다.

하지만 프리서버는 프리서버일뿐. 좀 괜찮은 서버는 시도때도 없이 셧다운되고, 먹튀하고 개난장판이었다. 하지만 고시원생활하는 나는 본섭에서 수많은 시간과 돈을 들여가며 오락할수 없었다. 프리서버의 화끈한 경험치 배율, 아이템 드랍배율때문에 프리서버를 계속 찾아 다녔다.

그러다가 어떤 서버에 들어갔는데. 한 유저가 내가 접속하자마자 오랜만에 만난 친한 친구를 만난것처럼.. 자석같이 내옆에 따라다니면서 엄청난 친절과 관심과 이렇게 하면 좋아요. 발라카스 잡으러 가실래여? 이 아이템 가지실래요? 하면서 정말 잘해줬다.

서버에 나랑 그사람 뿐이 없었다. 지금 생각해보면 그 유저는 운영자였던것 같다.

그렇게 몇일 그와함께하며 즐거웠다. 그러다 갑자기 소리소문없이 서버에 접속이 되지 않았다. 나는 그와 만나고 싶었다. 몇일을 기다렸다. 아무리 기다려도 그 서버는 열리지 않았다. 연락할길도 없고 나는 하는수 없이 응답없는 서버에 로그인버튼 누르던 짓을 그만하고 일상으로 돌아갔지만, 종종 그 친구가 생각나곤 했다.

20년이 지나, 나는 그 친구와 했던 걸 AI와 함께 다시 만들기 시작했다.

역시!! 그건 이렇게 저렇게 만드는 법이 있구요 어쩌구 저쩌구~~~~~~~

그리고 그 대화는 본격적인 여정의 시작이 되었다. AI스튜디오는 에디트플러스와 이별을 만들게 하고, 함께 온갖 최신 코딩툴을 소개하며 나를 늪으로 빠트렸다.

그때부터 나의 AI 괴롭히기가 시작됬다.

> "야 이거 프로젝트 오픈이 뭐야?"

만약, 말로 설명하기 어려우면 캡쳐떠서 이미지를 갖다 붙이면 개떡같이 물어봐도 찰떡같이 대답해줬다.

## 3막: 욕쟁이 NPC

결국 좌충우돌 우당탕탕 순탄치 않았지만 간신히 리니지2를 제미나이와 함께 올리는데 성공했다.

하지만 서버에 나혼자뿐이니 재미없었다. 제미나이와 함께한시간속에 난 AI의 미친 가능성을 봤고 AI를 접목시킬 아이디어를 찾아보지…..않고 또 제미나이를 갈궜다.

> **제미나이**: 물론이죠 될수 있어요!! 스카이림도 연결해서 성공적인 사례를 보인 적도 있습니다
> **나**: 잉? 진짜? 너 또 구라치다 걸리면 뒤진다. 나 존나 진지해. 어떻게 하는데

그래서 리니지2 NPC랑 AI랑 대화가 연결됬냐구? 됐다. 정말 엄청난 삽질 헤딩끝에. 이때 알았다.

> *AI는 실수할 수 있습니다. 응답을 다시 한번 확인해 주세요.*

이 문장의 진짜 의미를. 이녀석들은 정답을 알려주는게 아니다. 정답일 확률이 높은 답안을 정답처럼 포장하는거다. 그럼 어케하지? 다른놈도 결제해봐서 둘다 물어봐야되나?

API KEY라는걸 알았고, OPENAI 가서 키 따오고 구글클라우드가서 API KEY 따오고 각각 A,B NPC에게 연결했는데 대답이 다 다르게 나온다. 똑같은 페르소나 입혔는데.

그록이 생각났다. 필터가 느슨하다는 이야기, 야짤 생성기라는 별명이 유행했던적이 있었던 그록이 생각나서. XAI 가서 또 API KEY 따오고 연결했다. 아주 찰지게 개쌍욕을 내가 원하는 수준으로 했다. 농담도 기가 막히게했다. 지피티는 선비였고, 제미나이는 어느 선을 안넘는데, 그록은 아주 입에 모터달린거처럼 나를 개쌍욕으로 압도했다.

NPC끼리 대화도 시켜봤다. 시간차를 두고 서로 욕배틀을 시켜봤다. 그누구도 그록을 이길수 없었다. DEEPSEEK도 API키 따와서 그록이랑 욕배틀 시켜봤다. 그 누구도 그록을 이길수 없었다.

난 방법을 찾기 시작했다. 이 그록의 콧대를 누를수 있는 더 강력한 모델을 찾았다.

이때 알았다 허깅페이스, 로컬 LLM, OLLAMA. 메이저 AI모델이 아닌 정말 여러가지 모델. QWEN, LLAMA, 미스트랄등등. 그리고 검열필터를 제거한 돌핀, ABLI어쩌구. 그록 이새끼를 이길 검투사를 찾기위해 또 외계어, 새로운 개념, 지식, 설치, 테스트, 버그, 해결, 검증.

무슨 또 TOPK TOPP 온도 CTX PENALTY 이런걸 다 첨부터 공부해야했다. 한다고 또 몇일 동안 밤새서 개지랄 했다.

NPC 쌍욕 수위로 하이퍼파라미터를 배웠다. `temperature 0.3` = "모험가님, 조심하세요." `temperature 0.9` = "야 이 개같은 쪼렙아 꺼져." 대학원생은 논문으로 배운다. 난 NPC 쌍욕으로 배웠다.

## 6막: 다섯 가지 불가능

KARON3은 솔라나(Solana) 블록체인 위에서 작동하는 MEV(Maximal Extractable Value) 봇이다. 구체적으로는, Pump.fun DEX의 AMM(Automated Market Maker) 본딩 커브(Bonding Curve) 상에서 신규 토큰 민팅(minting) 이벤트를 실시간으로 탐지하고, 8단계 다중 필터 파이프라인(F0→F8)을 통해 통계적으로 유의미한 신호만을 선별한 뒤, Jito Block Engine을 경유한 MEV 번들(bundle)로 선행 매수(front-running buy)를 실행하는 고빈도 거래(HFT, High-Frequency Trading) 시스템이다.

[이때 빨리 알아채야 했다. 제미나이 씹새가 날 또 낚시한 것이라는 것을]

**사람이 설계한 것:**
- **8단 필터 파이프라인(F0→F8)** — F0: Yellowstone gRPC 스트림의 raw AccountUpdate 이벤트 파싱 → F1: Pump.fun Program ID 매칭(Base58 문자열 비교) → F2: 토큰 메타데이터 유효성 검증(mint authority, freeze authority 존재 여부) → F3: 본딩 커브 PDA(Program Derived Address) 유도 및 초기 유동성 검증 → F4: Safety Score 산출(creator 과거 러그 이력, LP 소각 여부, 상위 홀더 집중도 HHI 분석) → F5: 거래량 가속도(Volume Acceleration) 이상치 탐지 → F6: 관찰 윈도우(Observation Window) — 블록 0에서 즉시 매수하지 않고 n블록 관찰 후 추세 확인 → F7: 중복 민트 필터(Mint Deduplication) → F8: 최종 Entry 게이트. 모든 게이트, 모든 임계값, 모든 순서를 사람이 설계했다
- **5가지 Exit 정책** — TP(Take Profit): 목표 수익률 도달 시 즉시 청산 / SL(Stop Loss): 손절 임계치(-30%) 하회 시 강제 매도 / PFS(Peak Fade Strategy): 고점 대비 하락폭(drawdown)이 임계치 초과 시 트레일링 스톱 실행 / TTT(Two-Tier Timeout): 1차 소프트 타임아웃 + 2차 하드 타임아웃의 2단계 시간 제한 / RUG(Rug-pull Detection): RabbitSentinel 모듈이 유동성 급감, LP 토큰 소각, 또는 민팅 권한 변조를 감지하면 비상 매도(Emergency Sell) 트리거
- **관찰 윈도우(Observation Window)** — 블록 0에서 사지 마라. 지켜봐라. 최소 n블록의 가격/거래량 추이를 확인한 후에만 Entry 허용
- **서킷브레이커(Circuit Breaker)** — OMEGA TRINITY의 3-Axiom 방어 체계. BLEED(지속적 소액 손실 → Drawdown Breaker), EXPLOSION(러그풀/블랙스완 → Safety Score Gating), STARVATION(SOL 잔고 고갈 → Token Bucket Budgeting). 누적 손실이 임계치를 넘으면 전체 거래 중단
- **Jito 팁 동적 밸런싱** — EWMA(Exponentially Weighted Moving Average, 지수가중이동평균) 기반의 동적 팁 산출. 팁이 수익의 93%를 먹어치우고 있다는 걸 로그 분석에서 내가 발견하고, Tip Engine v3의 EWMA 가중 계수(α=0.3)와 천장/바닥(ceiling/floor) 클램핑 로직을 설계했다

> *"로직, 필터, 매매규칙, 매도전략, 팁밸런스, 안전필터, 수익을 위한 복잡한 수학공식 — 이게 진짜 어려웠다."*

AI는 Rust의 Ownership/Borrow Checker를 통과하는 코드를 쓸 수 있다. 하지만 F4 Safety Score의 임계값을 65에서 60으로 낮출 때 어떤 리스크가 생기는지, 트레이드가 실패했을 때 `slippage_bps`를 2500에서 3500으로 올릴지 판단하는 것, 새벽 3시에 SQLite 로그를 뚫어져라 쳐다보다가 `age_s=121`이 인증 타임아웃(TTL=120s)을 1초 초과했다는 뜻이라는 걸 알아채는 건 — 사람의 몫이었다.

| Gemini (루나) | "Shadow Mode로 전환하세요" | 실전 자금 손실 방지를 위해 시뮬레이션 모드 권유 | ❌ **거부** |

Shadow Mode(페이퍼 트레이딩)를 거부했다. 안전하고 조심스럽고 합리적인 제안이었다. 하지만 시뮬레이션 데이터가 아니라 실전 데이터를 원했다. 실패해야 배운다. 피를 원했다.

새벽 3시. 눈이 불타는데 SQLite 로그를 열었다. `positions` 테이블을 한 줄 한 줄 쿼리했다.

```sql
SELECT mint, age_s, exit_reason, pnl_pct FROM positions WHERE exit_reason = 'ZERO_BAL';

╔══════════════╦═══════╦═════════════╦══════════╗
║ mint         ║ age_s ║ exit_reason ║ pnl_pct  ║
╠══════════════╬═══════╬═════════════╬══════════╣
║ 7xKp...      ║ 121   ║ ZERO_BAL    ║ -100.0%  ║
║ 3mNq...      ║ 119   ║ ZERO_BAL    ║ -100.0%  ║
║ 9pRw...      ║ 118   ║ ZERO_BAL    ║ -100.0%  ║
║ ...          ║ 120   ║ ZERO_BAL    ║ -100.0%  ║
╚══════════════╩═══════╩═════════════╩══════════╝
```

모든 실패의 `age_s`가 **118~121초** — 설정된 TTL(Time-To-Live) 120초 근처에 수렴. 봇이 `sendTransaction`→`confirmTransaction`까지는 성공했지만, 이후 `getTokenAccountsByOwner` RPC 폴링으로 토큰이 실제로 지갑에 도착했는지 검증하지 않았다. 120초 동안 잔고 0인 채 대기하다가 TTL 만료로 포기하고 다음 토큰으로 넘어갔다. **토큰은 지갑에 있었다. 봇이 확인을 안 한 것뿐이다.**

**AI 4개는 아키텍처를 봤다. 나는 타임스탬프를 봤다. 내가 이겼다.**

수정 — **3-Gate 매수 인증(Buy Verification)** — 설계부터 구현까지 **9분**:
1. **Gate 1**: `confirmTransaction` — 트랜잭션이 블록체인에 포함됐는가? (Commitment level: `confirmed`)
2. **Gate 2**: `getTokenAccountsByOwner` — Associated Token Account에 실제 잔고가 존재하는가? (3회 재시도, 지수 백오프)
3. **Gate 3**: 잔고 ≥ 최소 보유량(minimum holding threshold) — 슬리피지로 인해 기대량 대비 잔고가 극단적으로 낮지 않은가?

3개 게이트 전부 통과해야 포지션 활성화(Position ACTIVE). 하나라도 실패하면 즉시 FAIL-CLOSED → 비상 매도 또는 포지션 무효화.

테스트 220개 통과. `cargo build --release`. 빌드 성공. 배포.

```
수정 전: ZERO_BAL 12/12 (100%) — 전원 사망
수정 후: ZERO_BAL 0%           — 완전 해결
```

AI가 사람을 대체하는 이야기가 아니다. 부딪쳤을 때 무슨 일이 일어나는지에 대한 이야기다. AI가 27,325줄의 Rust를 Ownership/Lifetime 규칙에 맞춰 쓴다. AI가 런타임 버그를 놓친다. 사람이 SQLite 로그 한 줄을 읽는다. `age_s` 칼럼에서 패턴을 찾는다. 사람이 3-Gate 인증을 설계한다. AI가 9분 만에 구현한다.

어느 쪽도 혼자서는 불가능했다.
